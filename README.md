# 接班彩排

“接班彩排”是一款面向家庭照护者的移动优先 Web 应用。它把一次令人焦虑的大交班拆成“在旁观察 → 短时离开 → 安静接班”三次可撤回的小练习。应用不需要账号或付费 API；家庭长期数据保存在照护者浏览器，随 `npm start` 启动的最小房间服务只在内存中保存短时双机彩排。

### 生产隐私与响应策略

首个公开 HTML 自身声明同源 CSP（脚本、连接、图片、Worker 等默认仅限本站）和 `no-referrer`，因此即使 GitHub Pages 的固定边缘层不能由仓库添加自定义响应头，首次干净访问也会立即受浏览器文档策略约束。Service Worker 接管后的在线与离线响应会统一带上 `Content-Security-Policy`、`Referrer-Policy: no-referrer`、`X-Content-Type-Options: nosniff` 和 `Permissions-Policy`；`tests/deployment-e2e.js` 会从页面内受控 `fetch` 验证这些实际响应头。`_headers` 保存同一份托管清单，供支持自定义响应头的静态提供商直接采用；本地 Node 服务从第一次响应开始就下发这些头。

GitHub Pages 的首个网络响应头由平台控制，本仓库没有伪称能改写它。当前页面不加载第三方脚本、字体或分析服务，所有静态资源均由同一 HTTPS origin 以明确 MIME 类型提供；真实家庭字段只写入当前浏览器的 `localStorage`。

## 运行

在 `/project` 中执行：

```bash
npm start
```

然后打开 <http://localhost:4173>。若要让同一局域网中的另一台手机加入，请在照护者设备上使用这台电脑的局域网地址（例如 `http://192.168.1.20:4173`）打开应用，这样邀请链接也会使用可访问的主机名。

房间邀请的来源不会信任 `X-Forwarded-Host` 或 `X-Forwarded-Proto`。未设置额外配置时，只允许 loopback、私有局域网 IP 和 `.local` 主机生成邀请；若以后把动态房间服务放进受管反向代理，必须显式设置只有 scheme 与 host 的 `PUBLIC_ORIGIN`（例如 `https://relay.example.com`）。

首次在线载入后，Service Worker 会缓存应用外壳，本机家庭设置和单机安全功能可以离线查看；双机配对和同步必须保持房间服务可达。一旦短时断线使授权新鲜度无法确认，替班者页面就会立即隐藏缓存的指导、来源、任务和搜索结果，禁用全部写操作并自动重连，只保留最后同步的红线以及照护者、当地紧急服务两个直接拨号入口。服务重启、房间记录消失或权限失效时也采用同一“仅可拨号”安全状态。

这不是推送服务。浏览器退到后台、手机休眠或页面关闭后，应用**不能保证收到通知或红线提醒**；直接电话才是不依赖页面保持打开的联系路径。

## 第一次打开

首次启动不会自动创建演示数据，而是提供两个明确入口：

- **体验演示家庭**：一键载入周岚家庭、5 条有来源的演示指导和 4 条明确标记为演示的结果记录（完成、中途结束、双方选择不同、双方选择延长）。适合快速查看诚实结果、严格匹配、待确认缺口、离班通知和撤回。
- **在电脑上建立我的接班彩排**：公开 URL 直接从真正空白的“我的家庭”进入第 1 / 6 步；刷新后从当前浏览器续接。不会带入演示成员、日期、指导、消息、结果记录或阶段结论，也不会请求房间 API。只有两台手机真实配对需要本地 `npm start` 与同一局域网。

演示入口会先打开一条约 2–3 分钟的评审导览，并始终显示“演示模式 · 脚本化样本 · 非真实家庭”。导览在同一页说明主要照护者、替班者和被照护者各自能做什么，依次展示在旁观察、短时离开和安静离班；顶部“演示模式 · 重播”可随时一键恢复演示种子。完整家庭工作区、单机路径、双机邀请、历史和脱敏导出仍可按需展开。

产品不替代微信、电话或紧急服务。它的切入口是把非正式的帮忙意愿变成演练过、有来源、可归属、可撤回的低风险交接证据，再用这些证据保护一小段不被普通消息打断的休息。

模式和设置进度都保存在 `localStorage`。关闭页面或刷新后，会回到上次完成的设置步骤。双机房间凭证也按角色分别保存在两台浏览器；服务重启会清空短时房间，家庭长期数据不会被上传到房间服务。

## 真实家庭：约八分钟的第一次设置

设置只收集第一次低风险“在旁观察”所需内容：

1. 主要照护者、被照护者、替班者、另一位紧急联系人及电话，并由用户填写当地紧急服务号码；系统不默认 120。
2. 一个具体休息目标、计划窗口和 10–60 分钟的短目标。
3. 把设备交给被照护者，由本人在专用页面当面同意。不同意或暂时跳过会被清楚记录，且不会解锁彩排；撤回后重新同意也必须回到这个页面。
4. 一个低风险日常情境、明确处理文字和真实来源。浏览器可选来源只有照护者、被照护者或替班者；它不能把录入文字标成专业来源。随匹配安全策略提供的演示专业参考是独立的只读记录。可用键盘或设备语音输入，保存前都要核对文字。
5. 核对可编辑红线和三条直接联系路径。保守示例不会自动成为家庭事实，只有用户点选或填写并保存的文字才会进入家庭数据。
6. 查看简短准备清单，然后开始真实的“在旁观察”。最低风险的第一次练习可在三人同处一室时把照护者手机交给替班者，并重新确认三方参与；完成这一步后，首页和“彩排路径”会把双机邀请标为推荐路径，让替班者改用自己的手机。同机彩排仍作为明确的备用入口；邀请弹窗也能先作废邀请，再进入同机的三方安全确认。

每次开始都会立即创建稳定会话 ID，并冻结当时的档位、计划时长、同意修订、指导版本与来源范围、红线、参与者、单机/双机模式和开始时间。结束后先保存应用能看到的事实，再由照护者和替班者分别回答。现场完成本身不会升级；只有双方都明确选择延长且满足保守条件时，下一次建议才前进。

空白或部分设置状态不会创建指导、结果结论、历史或消息。直接联系入口不依赖日常指导，也不会因设置未完成而被通知规则削弱。

## 结果记录：应用事实与参与者自报

会话结构当前为 `outcome schema v1`，保存在家庭浏览器；双机会话先由房间服务保留同一份短时事实快照，再以稳定会话 ID 幂等地并入家庭记录。

**应用记录（observed by the product）**仅包含产品确实能支持的事实：实际经过秒数、被点选完成的步骤、进入安静队列的普通更新数、待确认缺口及其普通/医疗风险状态、已记录的紧急事件，以及某个 `tel:` 联系入口是否被打开。最后一项始终显示为“已打开联系操作（不代表通话接通）”；应用不知道电话是否接通，也不知道对方是否采取了行动。

**参与者自报（self-reported）**按回答者分开署名和计时：

- 照护者回答休息活动是否发生、大约查看手机次数、是否被非紧急事项实际打断、重复相似时间窗的信心、是否感到不安全，以及延长 / 重复本级 / 退回一级。
- 替班者回答能否处理练过的范围、仍不确定的步骤、是否联系照护者、是否感到不安全，以及延长 / 重复本级 / 退回一级。
- 被照护者回答是可选的独立记录，可以是舒适度 / 偏好、“没有询问”或“本人不想回答”。它不会被照护者或应用暗中补全。

所有表单都允许保存部分回答。空白不推断心理健康改善、临床安全、放心程度或“已经可以”；趋势图只并排展示实际时长与当次自报信心，不宣称前者造成后者。

## 下一档建议

建议规则在家庭页面直接列出理由，不使用隐藏分数：

- 任一参与者选择退回，立即建议当前档位的前一级，历史不删除。
- 没有双方都选择延长（包括任一人选重复或关键回答缺失），保持当前档位。
- 未解决的医疗/高风险缺口或紧急事件使当前档位暂缓，并继续使用直接联系 / 现有专业参考路径。
- 只有会话在当前同意与指导授权下完成、应用结束事实齐全、照护者和替班者关键回答齐全、双方都明确选择延长、无人报告不安全且没有未解决紧急/医疗事件时，才建议延长一级。
- 照护者可随时把建议下调到更保守的档位。同意修订或指导版本变化会使旧建议失效，但不会改写旧事实。

首页汇总实际完成的离班分钟、完整独立交接、由产品延后的普通更新、紧急事件、最近信心 / 选择和带理由的下一档。历史详情把“应用记录”与三类“参与者自报”分开显示来源和时间。

“导出 / 打印家庭复盘”完全在本地生成，默认排除邀请能力 / 令牌、原始紧急电话号码和敏感会话备注；照护者可以明确选择是否包含备注与本人偏好。来源撤回后的报告沿用页面的遮盖规则，只保留适当的非识别汇总事实。

## 推荐演示路径

1. 在首次选择页点击“体验演示家庭 · 周岚家庭”，无需设置知识即可进入评审导览。
2. 先读三种角色和当前授权，再以替班者视角查看一个有本人来源的低风险匹配。
3. 进入短时离开，分别记录一个普通未知缺口和一个医疗 / 红线缺口；两者保持分离，红线页直接显示真实 `tel:` 联系入口。
4. 载入明确标记为演示的短时离开结束事实与三方署名回看。规则只在双方都选择延长、无人报告不安全、授权与事实齐全且没有未解决紧急 / 医疗事件时建议“安静接班”。
5. 在安静离班预览中确认普通更新只显示数量、停止与直接联系始终可见，并看到浏览器后台不保证提醒的限制。
6. 点击右上角“演示模式 · 重播”恢复种子；点击“查看完整演示家庭”按需展开历史、趋势、指导、双机与导出。
7. 若继续双机演示，在“三档彩排”点击“邀请替班者的手机”。两台手机仍需分别逐项确认受限范围、完整指导版本、红线和直接联系电话；替班者页面没有家庭主页、设置或历史。

## 双机房间与权限

- `POST /api/rooms` 创建 15 分钟有效的邀请。成功加入同时需要 URL 中的随机邀请能力、由照护者另行核对的人类可读短语，以及与家庭预先填写内容一致的替班者姓名。
- 姓名比较和短语只用于“预期参与者”核对，**不是身份证件、生物特征或现实身份验证**。家庭仍应当面或通过原本可信的电话单独核对短语，不应把邀请公开转发。
- 邀请只能成功使用一次。加入后服务器签发与照护者不同的替班者能力，以及稳定的房间会话 ID 和角色参与者 ID；两种能力只能调用各自角色的动作。
- 所有写操作都带当前房间 `revision`、一次性 `actionId`、会话 ID、参与者 ID、本人同意版本、主要指导版本和安全范围版本。服务器拒绝缺字段、旧版本、重复动作、未知字段、角色越权、结束后写入以及普通记录通道中的医疗/高风险文字。
- 浏览器与房间服务只使用版本化的 `safety-policy.js` 判断医疗/高风险文字，CI 会拒绝生产文件中的影子正则或分类器。服务端始终是最终信任边界：它对标题、处理文字、问题与复盘字段做 NFKC、大小写和分隔符归一化后跨字段重新判断，并自行生成 `highRisk`、来源显示、来源类型、分类、联系规则和安全范围版本。创建房间时，主要彩排必须是低风险且非“立即联系”内容。可搜索的高风险参考必须逐字段匹配同一策略模块中的版本化只读记录；仅提交专业 actor ID、护士/医生式来源标签、`highRisk`、`now` 或“立即联系”都不能建立专业来源，已知记录 ID 的标题或处理文字一旦被改动也会被拒绝。
- 每个房间响应都带安全策略版本，浏览器在所有房间 API 请求中回传同一版本。创建、加入、写入或搜索时版本不一致会返回 `policy_update_required`；两端隐藏房间指导和操作，显示“刷新更新后再继续”，并在已经取得电话的设备上保留直接拨号。
- 两台手机几乎同时操作而收到 `stale_revision` 时，客户端会在同一次点击中读取最新房间、生成新的 `actionId` 和完整版本上下文并自动重试；不要求用户凭感觉再点一次。连续变化超过重试上限时才明确暂停并提示稍后重试。
- 两端轮询按房间修订号单调合并，并把同一设备的刷新串行化；即使较早发出的读取在结束复盘后才返回，也不能把“已结束”界面回滚成旧的现场或复盘状态。
- 配对后两端必须分别明确确认本次范围、红线、联系电话，以及服务器在现场允许搜索的**全部**指导。预检会逐条显示每份指导的准确版本、来源和使用规则，而不只显示主要指导；服务器绑定确认时的完整版本快照，并在双方完成前拒绝开始。
- 家庭浏览器修改本人同意、当前指导、任何可搜索指导、红线或联系电话时，会把正在等待、配对、进行中或复盘中的旧房间标记为失效。被照护者撤回还会先持久化远端撤销请求，失败时重试，并在下次联网继续重试。
- 重签会同时作废旧邀请、旧会话和旧替班者能力；撤销、到期与被照护者撤回都会关闭旧访问。API 响应和 Service Worker 均禁止缓存房间数据。结束、撤销、失效或到期的内存房间只短暂保留供最终状态同步，随后由服务定时清除。
- 替班者页面不是家庭主页：不会收到家庭设置、历史、照护者能力或不可用指导，只收到本次服务器规范化并允许搜索的参考全集、三步状态、红线与直接联系电话；其中被策略命中的高风险参考只能是策略内置、逐字段验证且保持“立即联系”的只读引用。
- 服务只保存运行进程中的短时房间，不是生产级远程部署。服务重启会清空房间；真实跨网络使用需要 HTTPS、持久化会话存储、速率限制和受管部署。

## 数据、撤回与重置

状态使用版本化结构保存：指导包含稳定参与者 ID、来源类型、确认记录、版本、授权版本和可用状态。被照护者同意另有一份单调递增的本地授权记录；旧标签页或旧数据不能把撤回降级成旧授权。

撤回会立即把活动会话记录为 `revoked`，结束彩排和离班，撤销本人来源指导与旧接班确认。含已撤回来源的会话会删除 / 遮盖参与者、指导、红线、自由文本和自报内容，只留下适当的档位、时间、计数等非识别事实。重新同意会创建新授权版本，不会复活旧内容或旧建议。

旧版本的 `stageOneCompleted` / `rehearsalCompleted`、活动文案或百分比不会迁移成结果事实。它们只会显示“较早完成，详细结果未记录”，并提示做一次新的可测量彩排。

家庭设置中的“清空家庭 / 返回模式选择”会先显示明确的不可撤销确认。取消不会修改数据；确认后才删除当前家庭并返回首次选择。演示家庭也可以在同一确认页单独恢复为种子状态。

## 加密备份与恢复

真实家庭可从家庭设置创建完整恢复备份；空白设备的首次选择页也有“恢复加密备份”入口。它与“导出 / 打印家庭复盘”严格分开：

- **家庭复盘**是供人阅读的脱敏 JSON / PDF，默认排除电话、能力令牌和敏感备注，不能导回应用。
- **恢复备份**是版本化的加密信封，包含真实家庭、当前可保留的指导与历史。文件名以 `.relaybackup.json` 结尾，不能直接阅读，只有原密码可以解密。
- 有真实历史且没有备份或上次备份超过 30 天时，应用显示可暂停 7 天的提醒；刚建立但还没有会话的家庭不会被催促。成功生成文件后保存本设备的最近备份时间。恢复成功只写入可见的格式版本、恢复日期和成功结果，不持久化构建、同意门或记录计数。

备份完全使用浏览器 Web Crypto：密码经 Unicode NFC 归一化后，以 16 字节随机盐、PBKDF2-SHA-256、310,000 次迭代派生不可导出的 AES-256 密钥；内容使用 12 字节随机 IV 的 AES-GCM 加密。格式、信封版本、创建时间、KDF 参数和加密参数都作为附加认证数据，因此修改文件头或密文都会得到同一个“密码错误或文件被篡改”失败边界。信封和解密内容都不包含部署构建元数据。应用不保存密码，也没有服务端找回路径；创建与恢复表单都提供明确的显示 / 隐藏控制。

当前信封版本为 `2`，解密内容版本为 `2`。恢复前会先做 2 MB 文件限制、严格 JSON / Base64、精确字段、嵌套深度、节点数、数组、文字长度、危险原型键、算法和版本检查。家庭复盘、演示家庭、未来版本、未知顶层字段、活动会话、任意深度的双机邀请 / 身份 / 撤销能力与无效授权组合会被剥离或拒绝。创建备份会把本机正在进行的有效彩排保守结束为“中途结束”，同时清理倒计时与双机能力，不会留下仍在进行的历史。

输入正确密码也不会直接写入。应用先在内存中完成旧结构迁移，再用当前 `safety-policy.js` 重新判断指导、缺口与复盘，把历史会话中的关联缺口同步为当前风险 / 状态，并用当前 `outcome-model.js` 和策略版本重新规范结果与建议。随后预览来源格式、备份日期、最近历史、家庭与记录数、降级复核、同意门和覆盖时的重置摘要；已有真实家庭还可先创建一份当前备份。用户再次确认后，家庭状态、授权记录、双机加入能力和待重试撤销能力清理才作为一次可回滚的本地事务提交；任一步失败都保留恢复前家庭且不写审计标记。

被照护者自主权不会因备份回滚：空白设备不会把备份里的旧同意自动变成当前同意；当前设备已经记录的撤回也始终压过备份中的旧授权，即使备份版本号更高。恢复后会明确要求把设备交给本人重新当面确认。演示设置不提供真实家庭备份或恢复操作，演示记录也不能进入真实恢复。

## 安全边界

- 只调用当前获授权且有明确来源的指导；未知情境不会回退到看似相近的建议。
- 每个待确认缺口都持久化且可逐条复核，不限制为前三条；同一问题只增加遇到次数。
- 当前保守原型词表命中的胸部不适/发紧/压迫、呼吸困难/不畅/费力、脉搏或心率缓慢/过快/微弱、异常生命体征、苍白/发绀、意识变化、抽搐、跌倒/受伤/出血、发热/过敏/呕吐、用药/剂量、急救/搬动等文字会进入医疗/高风险路径。全角、大小写、空格、标点、零宽字符和跨字段拆分不能把测试词组降级；家庭来源也不能把它们变成现场处理指导。
- 医疗待确认表单不会提供可选择的专业 actor。即使修改 DOM、导入旧数据或写入“护士/医生”式来源标签，文字也只能继续留在医疗待确认状态；浏览器不会据此创建当前确认或可搜索指导。内置演示专业参考随策略版本提供且不能编辑。
- 日常处理范围只从当前可用指导实时生成；来源撤回后，升级规则和离班范围会同步收缩。
- 红线是家庭编辑的联系规则，不是临床保证。照护者、紧急联系人和用户填写的当地紧急服务 `tel:` 入口始终保留。
- 系统不生成诊断、急救、搬运或用药决定。首版只覆盖两小时以内的低风险陪伴和一般生活协助。

这里的关键词/策略筛查只是保守的原型护栏，不是临床分诊，也不声称覆盖所有症状、表达方式、语言或医疗风险。出现实际健康疑虑时应使用直接联系和当地紧急服务，而不是依赖分类结果。

## 验证

```bash
npm run check
npm run build
npm run test:outcomes
npm run test:policy
npm run test:recovery
npm run test:e2e
# 提交前或开发中需要完整审计时
npm run test:e2e:full
```

`test:policy` 先检查单一策略所有权、页面/Service Worker 缓存版本一致性，再从干净进程通过真实 HTTP 请求覆盖房间创建、加入、普通记录、搜索、红线、待确认缺口、复盘和最终完成。维护表目前包含 67 条中文/英文高风险正例与 23 条低风险反例，并对空格、标点、零宽字符、NFKC/全角和大小写变换做属性式检查；其中包含“胸口发紧、呼吸不畅、脉搏缓慢”在创建、搜索、替班者记录、照护者收尾和跨字段复盘中的回归，也验证专业 actor/立即联系字段、伪造来源标签和已知引用 ID 都不能授权被改写的本地处理文字。

`test:outcomes` 先用纯规则表覆盖真实空状态、三档会话、部分回答、不同选择、任一人退回、紧急/医疗暂缓、未完成与断线状态、旧同意 / 指导、下调覆盖、幂等 ID、事实汇总和撤回遮盖；再在隔离端口运行双角色服务与浏览器，验证固定开始快照、安静文字结束前隐藏、断线事实、重复结束拒绝、角色不可代答、桌面历史、窄屏回看、默认脱敏 / 可选敏感备注报告，以及旧布尔完成不生成指标。

`test:outcomes` 同时运行纯结果规则表和真实双角色 HTTP / 浏览器回归。后者明确覆盖“现场结束时没有缺口、双方都选择延长，但照护者在结束后的来源复盘首次记录医疗/高风险缺口”的路径：服务器必须把该缺口并入同一稳定会话的 `summary.facts.pendingGaps`，本地持久记录也必须保留关联，下一档只能得到 `medical-hold`，不能进入安静接班。

`test:recovery` 先以真实 Web Crypto 覆盖 PBKDF2 / AES-GCM 往返、无部署元数据、明文不可见、任意深度能力剥离 / 拒绝、错密码、头部 / 密文篡改、未知版本、超大文件、复盘误导入、演示隔离和危险原型键；再用真实 Firefox 覆盖下载 / 恢复、密码显示控制、活动会话保守关闭、零 `fetch`、干净设备重新同意、旧撤回单调保护、两类双机能力清理、模拟存储故障的原子回滚、最小恢复审计、320px 预览 / 重置摘要 / 当前备份入口、零记录不催促与提醒暂停，以及当前安全策略 / 结果模型对恶意但正确加密内容的重新验证。

`test:e2e` 是给独立评审和持续集成使用的快速浏览器门禁：它在进程内监听隔离的随机端口。原有门禁覆盖空首次启动、当次三方确认、严格匹配、缺口去重与单调解决、明确来源、即时撤回、刷新后遮盖和手机宽度；新增评审门禁覆盖真实家庭诚实空状态、一键导览、完整故事与重播、角色 / 同意可见性、键盘与对话框语义、长中文、320 / 390px / 桌面布局、直接拨号，以及页面没有无依据的成功或安全承诺。它不复用 4173 端口，因此多个评审同时运行也不会互相终止服务。

`test:e2e:full` 保留原有完整浏览器安全审计；未提供 `BASE_URL` 时会在隔离的随机端口启动并在结束后关闭服务，提供 `BASE_URL` 时则验证指定地址。完整覆盖包括首次选择、真实空状态、暂停/恢复设置、本人同意、在旁观察、同机与双机邀请层级、安全匹配、来源复盘、安静队列、撤回和重连。结果 / 建议规则的新增验收由 `test:outcomes` 专门覆盖，避免把旧的二元解锁断言继续当成产品要求。
